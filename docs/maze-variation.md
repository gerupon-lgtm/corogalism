# T-278・T-279 迷路の緩急とバリエーション / v0.6.22

**v0.6.22:** 序盤8面を7×7とし、9面から大小を混ぜる。広場の砂・力場・対応する休憩ととりもちを両区画へ分散。他の広場にも壁際から抽選したとりもちをときどき混ぜる。ゴールへの誘導を逆算しない。[配置の詳細とモード差](open-floor-pacing.md)。

**v0.6.21:** 公開画面で長い面名が音・ポーズの領域と重なる例を確認し、面名を折り返し、ボタンの幅を確保。読み上げの「7×7固定」も現在の盤面に合わせて更新。迷路生成・物理・時間・げんき・記録条件はv0.6.20から維持する。

同じマス数でも道の長さや曲がり方が変わり、マス数が変わると見渡し方と操縦の細かさが変わる。107面・約1600秒のやさしいモード試遊で感じた単調さに対し、この違いを公開済みの素材で組み合わせる。

## 本編の選択

チャレンジの1〜8面は7×7。9面から7×7・8×8・9×9・11×11・13×13を乱数で混ぜる。後半ほど大きくする解禁方式ではない。13は計算上の上限ではない。15・17・21も条件を指定して検証する。見づらい面や難しい素材の組み合わせを、検証前に除外する方針にはしない。

| 形 | 生成と狙い |
|---|---|
| 迷路 | 既存の自動生成による道と脇道 |
| 入り組んだ道 | 複数候補から長い経路を選び、同じ7×7でも迂回を増やす |
| すなおな道 | 短めの経路を選び、後半にも息抜きを混ぜる |
| 広い曲がり角 | 一部の壁を開け、複数の道や広い角を作る |
| 反発の広場 | 内壁を減らし、ゴムの仕切りと既存の床を使う |

固定の迷路画像・壁配置は使わない。種から形を生成し、壁を加工した後に全マスへ進めることと最短経路を確認する。床の配置処理が、選んだ大きさや長い経路を基本の7×7へ置き換えることはない。

直近4面と同じ大きさ・形・素材は出現確率を下げる。候補からの除外や「必ず次は簡単」という固定順ではない。1面目は素直な7×7、床の初紹介は従来の16面までの順番を使い、その後の素材は種と履歴で選ぶ。100面以降にも小さな面・短い道・大迷路・広場が混ざる。通常限定の10面ごとの「光の滑走路」は残す。

## 素材と反発の広場

本編はビー玉と既存の床・壁を使用する。金属・木・スーパーボール・スポンジはボールおためしに残し、綿の吸収壁・スライド壁・回復壁は未実装の候補のまま。

広場は乱数で向き・位置が変わる仕切りを残し、一定の傾きで壁に当たらずゴールへ直行する道を遮る。追加の短い仕切りも種から配置し、全マスの到達性を確認する。基本壁はゴムとし、選んだテーマの石・トゲ・こけは既存の割合で残す。v0.6.22では力場を両区画へ分散し、開始位置と仕切り出口を保護する。半径と力の強さは既存値を使い、壁が力を遮断する機能は追加しない。砂・休憩・とりもちも両区画へ配置する。

**反発回数は新しいクリア条件にしない。** 丁寧に傾きを変え、壁を避けてクリアする遊びは認める。「一発の固定傾きによる無衝突ゴールを防ぐ」という配置の要件と区別する。

曲がり角が足りず重力・反重力を配置できない場合は、経路上の離れた候補へ不足した向きの力場を補う。選んだ素材が表示名だけにならないようにする。砂・力場・休憩・とりもちは脇道にも配置し、取得物はゴールへの経路上に置く。

## ルール・表示・記録

初期げんきは従来どおり `40 + 4 × 最終経路の折れ数`。制限時間も既存の経路長・折れ数・砂・力場・やさしいの余裕から計算する。形ごとの追加ボーナスや面数による難化は導入しない。

勢いがある時にゴールを通過しても取りこぼさないよう、更新後の位置に加えて実際に移動した区間を判定する。止まる必要はなく、死亡・時間切れが同じ更新で起きた場合の優先順位は従来どおり。

開始とプレイ中の面名に大きさ・形・素材を短く表示する。毎面の説明画面や新しい待機は追加しない。ガイドの既存の一文へ、大小と反発の楽しさを加える。描画の固定照明計算と画像領域を使い回し、物理や素材の性質を変えずに毎フレームの負荷を減らす。

コンティニューでは同じ種・形・素材と休憩床の使用状態を維持する。新構成の記録は通常が `corogalism-run-bests-maze-v1`、やさしいが末尾 `-easy` に保存する。旧 `floor-v1` の107面などは消さず、タイトルの旧記録欄へ参考表示する。クリア直後の保存とノーコン／使用済みの分離は維持する。

練習・床の練習・はじめての遊び方・両おためしの形や採用値は変更しない。次の面の待機1秒と彩度の復帰0.3秒、終了確認、音、縦向き固定・全画面の対応範囲も維持する。

T-278の検証条件と成功・失敗は[確認記録](verification/maze-variation.md)、T-279の追加確認は[今回の記録](verification/open-floor-pacing.md)。実機の長時間の面白さと負荷は、公開試遊で引き続き確かめる。
