# センサーを使う遊び：実装済みと追加候補

**現在地（2026-09-22）:** 自然脱出・画面連打・本体タップによるとりもち脱出は実装済み。本体タップ感度も実機確認完了。静止回復は「ひとやすみ」として実装済み（球の速度・移動量で判定し、端末の揺れ幅を直接判定する案とは別）。追加センサー遊びは下記「提案候補」の未採用案。

**v0.4.0追記:** 葉っぱ・休憩床・とりもち床（時間／ダブルタップ／本体タップ脱出）は今回実装。最新仕様・確定値は [leaf-floors-pwa.md](leaf-floors-pwa.md)。以下の「将来案」は当時の記録です。

2026-09-13。ユーザーは、傾きに加えてスマートフォンの物理センサーを使う遊びを検証したい。以下は検討用で、現行ゲームの動作は変更しない。

## 以下は初期検討の履歴：とりもちからの脱出

- 一定時間が経過すれば必ず脱出できる。
- 画面のダブルタップや、本体への軽い衝撃で脱出を早める要素を持たせたい。
- とりもちのランダム配置／面コンセプトに合わせた固定配置は後で相談。

## 当時の検証計画（現在の未完了一覧ではない）

- 画面のダブルタップはタッチ入力の連続として検出する。筐体への軽いタップは短い加速度変化から推定する別の入力経路とする。
- ブラウザのモーション情報から筐体のどの場所を叩いたかを直接特定できるわけではない。ケース・持ち方・機種・サンプリング周期による検出差を実機で調べる。
- 拘束中だけ脱出操作を受け付け、通常の傾け操作・持ち替えとの誤判定を抑える。
- 強さに比例して無制限に効果を増やさず、軽い操作の検出1回につき一定量だけ拘束時間を短縮する案。
- 1回の画面タップがタッチとモーションの両方で検出されても、二重加算しない。
- タップ間隔・モーション判定値・短縮量・連続受付間隔は調整可能にする。数値は未確定。
- センサーが取得できなくても時間経過と画面操作で遊べる。動きの許可が必要な環境では、明示的な開始操作から要求する。
- 脱出後すぐ同じ床に捕まり直さない猶予、制限時間の扱い、触覚・音・表示のフィードバックは後で決める。

## 提案候補（未採用）

| 案 | 操作と遊び | 検証対象 |
|---|---|---|
| ゆらしてほどく | とりもちに捕まった球を左右に小さくゆすり、粘りをほどく | 加速度・角速度の周期、通常操作との区別 |
| ぴたりと静止 | 小さな台で一定時間安定させると回復などの効果 | 傾きの揺れ幅、静止検出 |
| ひねる円盤 | 対象エリアで端末を小さくひねり、円盤を回して進む方向を合わせる | 角速度、傾き移動との干渉 |
| そっと運ぶ | 壊れやすい荷物を運び、急な動きを抑えるとボーナス | 短い加速度変化の検出、持ち方・端末差 |
| リズムで弾む | 特定の台で軽いトントンを一定リズムで入力し、ばねをためる | 衝撃の時刻・間隔、二重検出防止 |

## 検証の進め方案

まずはダブルタップと軽い衝撃によるとりもち脱出を比較する。次に静止や小さい揺れを試す。
開発用の検証画面で、センサー値・検出タイミング・実際の操作を照合する。画面上の数値を本編で常時表示することは意図しない。

参照（2026-09-13確認）：
- [MDN: devicemotion](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicemotion_event)：加速度と回転速度。
- [MDN: requestPermission](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent/requestPermission_static)：対応環境での許可とユーザー操作起点。
- [MDN: pointerdown](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointerdown_event)：画面接触の入力。
