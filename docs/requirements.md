# 要件（フェーズ1）— 機能IDの正典

決定の根拠と経緯は `../../構想たたき台_傾き操作迷路ゲーム.md`（親フォルダ）が正典。本ファイルはフェーズ1の実装範囲を機能IDに落としたもの。

区分: 印なし＝確定 ／ **【想定】**＝文脈からの仮置き（要チェック） ／ **【要確認】**＝未定

## 1. 入力（フェーズ0で実機検証済み）

| ID | 機能 | 内容 | 必須度 |
|----|------|------|--------|
| F-101 | 傾き入力 | `DeviceOrientationEvent` の beta/gamma を取得し、キャリブレーション基準からの差分を傾きベクトルへ正規化する | 必須 |
| F-102 | iOS許可取得 | iOS 13以降は `DeviceOrientationEvent.requestPermission()` を**ユーザー操作を起点に**呼ぶ。HTTPS必須 | 必須 |
| F-103 | キャリブレーション | ユーザーが「フラットとみなす姿勢」を任意に決められる。**プレイ中も再実行できる** | 必須 |
| F-104 | 擬似傾きモード | 画面のタッチ／クリック位置を傾きベクトルに読み替える。押している間だけ有効 | 必須 |
| F-105 | 入力の抽象化 | F-101 と F-104 を共通の傾きベクトル（向き＋強さ、大きさ1以下）へ正規化し、ゲーム本体からモード差を隠す | 必須 |
| F-106 | フォールバック | 許可拒否・センサー非搭載・センサー値が届かない場合、擬似傾きモードへ自動で着地する。**行き止まりを作らない** | 必須 |
| F-107 | 入力の平滑化 | `inputSmoothing` によるローパス。既定 0.35 | 必須 |

## 2. 物理

| ID | 機能 | 内容 | 必須度 |
|----|------|------|--------|
| F-111 | 転がり物理 | 傾きベクトルを加速度へ変換し、速度・減衰・位置を固定タイムステップで積分する | 必須 |
| F-112 | 衝突解決 | 円（ボール）× 矩形（壁）の最近点による押し出しと法線方向の速度反射。セル単位のクランプにしない | 必須 |
| F-113 | トンネリング対策 | 速度上限とサブステップ分割 | 必須 |
| F-114 | **パラメータの層構造** | 実効値 = 基準値 × キャラ × 素材 × ゾーン → クランプ。`resolveParams` 経由で解決する。`docs/physics.md` が契約 | 必須 |
| F-115 | 素材・キャラ・ゾーンの定義構造 | フェーズ1では素材 `default` 1種類、キャラ1体、ゾーンは空。**構造だけ用意する** | 必須 |

## 3. 基準値（フェーズ0の実機計測結果・確定）

| パラメータ | 値 | 備考 |
|------------|----|------|
| `tiltSensitivity` | 17（マス/s²） | 両端末で完全一致 |
| `friction` | 2.5 | Pixel 2.6 / iPhone 2.5。指数減衰の係数 |
| `maxTiltAngleDeg` | 25 | Pixel 23 / iPhone 26 の中間。**ユーザー設定項目にする** |
| `wallRestitution` | 0.35 | 両端末で完全一致 |
| `inputSmoothing` | 0.35 | 初期値から変更なしで通った |
| `ballSizeRatio` | 0.55 | キャラ側の属性。固定値ではない |
| `mazeSize` | 7 | フェーズ1固定。生成関数は引数で受ける |

端末差を吸収するセンサー実装は**不要**（両端末で感度・反発・平滑化が一致したため確定）。

## 4. 迷路

| ID | 機能 | 内容 | 必須度 |
|----|------|------|--------|
| F-121 | 迷路自動生成 | DFSバックトラッカー。サイズとシードを引数に取る純粋関数。**後続2作が使える独立モジュールとして書く** | 必須 |
| F-122 | 到達可能性検証 | BFSで全セル連結を検証する。生成の一部として必ず通す | 必須 |
| F-123 | シード指定 | シード値を指定して同一の迷路を再生成できる | 必須 |
| F-124 | 1画面完結 | 迷路は画面内に収める。カメラは動かさない。**ただしカメラは差し替え可能な抽象にする** | 必須 |

## 5. ゲーム進行

| ID | 機能 | 内容 | 必須度 |
|----|------|------|--------|
| F-131 | ゴール判定 | ゴールセルに到達したらクリア | 必須 |
| F-132 | リトライ | 同じ迷路をやり直せる | 必須 |
| F-133 | 次の迷路 | 新しいシードで次の面を生成する | 必須 |
| F-134 | タイム計測 | 最初に動き出した時点から計測する（フェーズ0と同じ判定） | 必須 |
| F-135 | 自己ベスト | シードごとのベストタイムを `localStorage` に保存する【想定】 | 必須 |
| F-136 | 壁ヒット数 | 参考値として表示する | 推奨 |

`localStorage` が読めない環境（プライベートウィンドウ等）でも動作すること。

## 6. 画面・設定

| ID | 機能 | 内容 | 必須度 |
|----|------|------|--------|
| F-141 | タイトル画面 | 初回のキャリブレーション導線（F-102 のユーザー操作起点を兼ねる） | 必須 |
| F-142 | ゲーム画面 | 盤面・タイム・壁ヒット数・一時停止 | 必須 |
| F-143 | クリア画面 | タイム・自己ベスト・使用シード・リトライ／次へ | 必須 |
| F-144 | 設定画面 | 操作モード切替、最大傾き角、キャリブレーション | 必須 |
| F-145 | 開発中の注記 | 「開発中の技術検証です」を常時表示し、`noindex` を入れる | 必須 |
| F-146 | 横向き警告 | 縦持ち前提。横向き時は警告表示のみ | 推奨 |

## 7. 非機能

- 60fps目安【想定】。傾き操作は入力遅延が体感に直結する
- バックエンドなし。外部API・LLMを使わない
- PC（擬似傾き）とスマートフォン（傾き）の両対応
- 対応: Pixel 6a（Android/Chrome）、iPhone XR（iOS/Safari）で確認する

## 8. フェーズ1の判断ポイント

実装完了後、発案者が実機で評価する: **「もう1回やろうと思うか」**。

合わせて、フェーズ0の合格ライン a〜e が再編後も維持されていることを回帰確認する（T-116）。

## 9. 【要確認】

- 1面のプレイ時間の目安（フェーズ1で実測して決める）
- 難易度カーブの上限マス数（21×21 は実寸では厳しい。速度・制限時間とセットでフェーズ2以降に判断）
- 自己ベストをシードごとに持つか、面の通し記録として持つか【想定】ではシードごと
