## T-227: v0.3.1 初回操作のSE（2026-09-13）

- 症状：音ONを保存していても、ページを開いた後の最初の操作だけ選択SEが鳴らず、2回目以降は鳴る。
- 原因1：初回クリックで音声取得・デコードを開始するため、その時点のselectはバッファ未準備で破棄される。
- 原因2：初回モード選択ではセンサー確認中にボタンをdisabledにするため、共通クリック処理の対象外になる。
- 操作音だけ承認済み `se-select.wav` のPCMをJSに同梱し、AudioContext作成時に同期でバッファを用意。音色・サンプルは変更しない。他の音源は従来どおり音ON後に取得。
- `tools/embed-select.mjs` で `src/audio/selectBuffer.js` を再生成可能。元WAV変更時は再生成する。全サンプル一致をテスト。
- 音声resume待ちのselectだけ最大250ms、最新1件を保持。停止・ミュート・非表示・期限切れで破棄。過去の衝突音やカウント音は後から再生しない。
- 初回モード選択は画面遷移後に明示的にselectを1回鳴らす。共通クリック処理からpractice/challengeを除き二重再生を防止。
- 音ON切替にも同じ短い操作音を付ける。音OFF・SE音量0の条件を維持。
- BGMの「スタートSE後0.2秒」「プレイ中のみ」「毎回先頭」「ループ」は維持。
- `tools/browser-first-sound.mjs` は他の音源の通信を止めた状態で、ページ初回の難易度選択／設定／プラクティス／チャレンジから実際に操作音のSourceが1回開始することを検証。修正前は初回が0回で失敗することを再現済み。
- 検証：97テスト成功、初回4操作のブラウザ検証成功、既存browser-audioの全フロー成功。Standards / Specレビューとも指摘0件。
- 公開確認：v0.3.1（4bbef7a）、正式URLで初回4操作の検証成功。実機での聞こえ方はユーザーの再確認待ち。
