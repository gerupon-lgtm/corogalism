# 更新チェックが遅い場合のロジック監査

**v0.8.15対応済み：** 新版の検出と資材準備の表示を分離した。以下はv0.8.13を対象とした当時の監査結果。現行仕様と検証は[release-v0.8.15.md](release-v0.8.15.md)を優先する。

2026-10-25、v0.8.13の `src/pwa.js` と `sw.js` を対象とした確認。ユーザーの「ロジックに問題がないか確認」の依頼に対し、更新処理自体は変更していない。

## 確認済み

更新チェックは、新しい版の有無の確認と、その版の全資材を保存する準備を一緒に待つ。134資材、合計39,743,018 bytes（約39.7MB）で、このうちBGM5曲は30,368,104 bytes。待ち受ける資材には音源も含まれる。通信やブラウザの取得処理によって準備が長くなる場合がある。毎回この全量がネットワークで転送されるかは配信側・ブラウザの応答によるため断定しない。

画面上の待ち時間は `UI.updateCheckTimeoutMs = 15000`。ただし時間切れは資材取得を止めない。裏で準備が完了すると更新案内が出る一方、「更新を確認できませんでした」の結果文はそのまま残る。準備中と確認失敗が混ざる表示には改善余地がある。

## ローカルの実ブラウザ再現

ゲームの実際のpwa.js・sw.jsを使い、ローカルサーバーが返すキャッシュ版と、音源1本の応答だけを制御した。既存の音源や更新処理の本体は変えていない。

| 条件 | 測定結果 |
|---|---|
| 新版なし | 約2.44秒で「最新版です」 |
| 新版を検出し、音源の応答を保留 | 約187ms時点で新版のインストールが進行中だが「確認中」のまま |
| 保留した音源を返す | 開始から約714msで準備完了・更新案内を表示 |
| 音源を15秒以上保留 | 約15.08秒で確認失敗と表示し、ボタンを再び押せる状態へ戻る。取得は継続中 |
| 時間切れの後で音源を返す | 約15.28秒で更新案内が出るが、結果文は確認失敗のまま |

エラー0。これは制御したローカル環境の時間であり、実機での通信時間ではない。無限にボタンを無効のまま待つ動作は、この条件では再現しなかった。非表示タブ等で処理が止まる場合の実時間までは保証しない。

## 改善する場合の方向

監査時のおすすめは「新しい版の確認」と「更新データの準備」を別の状態として表示すること。全資材の準備が終わるまでは更新を適用しない仕組みを保ち、新版を見つけた段階で「更新の準備中」と伝える。準備中を一律に確認失敗と扱わないようにする。監査時点では未実装だったが、後続の依頼でv0.8.15に採用した。
