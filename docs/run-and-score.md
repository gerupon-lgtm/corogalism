## 1. なぜラン構造が必要か

フェーズ1はステージ型（1面ごとに独立、自由にやり直せる）だった。この構造のままHPを入れても、
**HP0で失うものが無い**ためゲームオーバーが痛くない。やり直せば元通りになる。

面数スコアも同じで、**ラン（通し）の器があって初めて意味を持つ**。
だからHPとラン構造はセットで入れる。姉妹プロジェクトのAmazingMazeも、エンドレスのスコアアタック型で確定している。

## 2. 2モード構成（確定）

| モード | HP | 面 | 主指標 | 終了条件 |
|---|---|---|---|---|
| **チャレンジ**（主モード） | **あり** | ランシードから連続生成、難易度上昇 | **到達面数** | HP0・時間切れ（コンティニュー可） |
| **プラクティス** | **なし** | シード指定の1面 | **クリアタイム** | ゴール到達 |

- **プラクティスはHPなし**（確定）。壁に当たっても死なず、純粋なタイムアタックになる。
  フェーズ1で作ったタイムアタックと自己ベストがそのまま活きる
- デイリーチャレンジ（固定シード）は将来プラクティス側に置く
- 2モードの性格を意図的に分けている。チャレンジは「失敗できない緊張」、プラクティスは「1/100秒を詰める」

## 3. ラン

### シードの導出

ラン全体を1つの `runSeed` から導出する。

```js
stageSeed(runSeed, n) = (runSeed * 2654435761 + n * 40503) % 1000003
```

**これでラン全体が再現可能になり、「同じランを他人と競う」ことができる。**
将来のデイリーチャレンジ（その日のrunSeedを全員共通にする）の土台にもなる。

### HPの扱い

**HPは面ごとにリセットする（持ち越さない）。** 各面の開始時に `40 + HP係数 × 折れ回数` で再計算する。

持ち越しにしない理由:
- HP初期値を折れ回数で決める設計（面ごとの公平性の根拠）が薄れる
- 回復アイテムが必要になり、一気に複雑化する

結果として「**1面ごとに全力、でも失敗は許されない**」という緊張になる。
失うのはHPではなく、積み上げた面数。

### コンティニュー

**無制限にするとゲームオーバーが無意味になる**ため、制限をかける。

- 1ランに **2回**まで【想定・調整前提】
- 失敗した面から、**HP満タンで再開**。到達面数は維持する
- 記録は2本持つ:
  - **ノーコンティニュー到達面数**（本命の記録）
  - コンティニュー込み到達面数（先に進んで新しい面を見るための記録）

**記録を分けるのが効く。** コンティニューで先を見る楽しみと、ノーコンで記録を狙う緊張が、
互いを壊さずに両立する。フェーズ3のスター評価・実績の軸にもそのまま繋がる。

## 5. 制限時間と難易度カーブ

### HPだけでは終わりが来ない（実測で判明）

最初はHPと素材の危険度だけで難易度カーブを作るつもりだったが、`tools/run.mjs` で測って破綻が分かった。

```
HPのみ・難易度カーブ3案とも   目標4.0 / 4.5 → 80面（上限。永遠に終わらない）
                              目標4.8      → 3〜14面
                              目標5.0      → 0〜4面
```

**閾値以下の接触は無傷なので、壁に当てない走り方をする限りHPは1も減らない。**
難易度カーブをどれだけ急にしても、当たらない人には効かない。
これでは到達面数が「腕前」ではなく「根気」の指標になってしまう。

**足りないのは、丁寧に走っても避けられない圧力。それが制限時間。**

### 制限時間（確定）

```
制限時間 = 経路長（マス） × 1マスあたりの秒数(面数)
```

**HPを折れ回数で正規化したのと同じ考え方**を、時間には経路長で適用する。
生成された迷路によって難易度がばらつくという問題（構想たたき台の付録Aで指摘済み）は、
これで解ける。

面が進むと「1マスあたりの秒数」を削る。**これが careful play では避けられない難易度カーブ。**

### 噛み合い方

```
制限時間が速さを強いる → 速く走ると壁に当たる → HPがミスを罰する
```

HPは**罰**であって、**圧力**ではない。圧力を作るのが時間の役目。

### 検証データ（自動操縦・ラン100回）

`urgency` は「間に合うペースに対してどれだけ余裕を持って走るか」（1.0=ぴったり、1.3=3割速く）。

| カーブ | urgency 1.00 | 1.15 | 1.30 |
|---|---|---|---|
| **緩** 0.55→0.28（20面で底）, dmg +4%/面 | **中央値12面**（時間切れ100%） | 14面（HP0 7%） | 15面（HP0 38%） |
| 中 0.50→0.26（15面で底）, dmg +6%/面 | 7面（時間切れ100%） | 9面（HP0 9%） | 10面（HP0 50%） |
| 急 0.45→0.24（12面で底）, dmg +9%/面 | 4面（時間切れ99%） | 6面（HP0 8%） | 7面（HP0 49%） |

**読み取れること（設計上いちばん重要）:**

- **時間切れとHP0が両側から挟む。** 慎重に走ると時間切れ、攻めるとHP0。
  **速すぎても遅すぎても終わるので、プレイヤーは自分で最適点を探すことになる**
- 急ぐほど到達面数は伸びる（12→14→15面）が、HP0のリスクも上がる（0%→7%→38%）。
  **リスクとリターンが釣り合っている**
- HPだけ、時間だけでは、この構造は出てこなかった

### 採用（確定）: 緩

```
1マスあたりの秒数 = max(0.28, 0.55 − 0.27 × (面数−1) / 19)
ダメージ倍率      = min(2.0, 1 + 0.04 × (面数−1))
HP係数            = max(3.0, 4 − 0.06 × (面数−1))
迷路サイズ        = 7×7 固定
```

**狙いの範囲（10〜25面）に入ったのは緩だけ。** さらに、この自動操縦は最短経路を完璧に辿るため、
**道を間違える人間のプレイはこれより短くなる。** 安全側に倒して緩を出発点にする。

検証コード: `tools/run2.mjs`（数値を変えたらこれを回す）。
`tools/run.mjs` は第1版で、HPだけでは終わりが来ないことを示す記録として残してある。

### マスは 7×7 で固定する（重要）

**マスを細かくする方向は採らない。** 理由が2つある。

1. 実寸比較で操作精度の限界を確認済み（7×7が下限の粗さ、21×21は厳しい）
2. **サイズを上げると折れ回数が増え、HP初期値も自動で増えるため、難易度が相殺される。**
   せっかく避けた「難易度の平坦化」が、難易度カーブ経由で復活してしまう

### 補助レバー（素材）

| 面が進むと | 効果 |
|---|---|
| `spike` / `stone` の比率が上がる | 同じ盤面が痛くなる |
| `moss`（安全地帯）が減る | 逃げ場がなくなる |

上の「ダメージ倍率」は、素材の危険度上昇を1つの数字で代理したもの。
実装では素材の配置比率として表現し、実装後に `tools/run2.mjs` で再検証するとよい。

## 6. データモデル

```js
// ラン（チャレンジモードの進行状態）
Run = {
  runSeed,            // ラン全体の種
  stageIndex,         // 現在の面（1始まり）
  clearedStages,      // クリアできた面数 = スコアの主指標
  totalTimeMs,        // 合計タイム
  noDamageStages,     // ノーミスでクリアした面数
  continuesLeft,      // 残りコンティニュー回数
  usedContinue,       // 一度でも使ったか（記録の振り分けに使う）
}

// 自己ベスト（localStorage）
RunBests = {
  noContinue:   { stages, totalTimeMs, at },
  withContinue: { stages, totalTimeMs, at },
}
```

プラクティス側の `BestRecords`（シードごとのタイム）はフェーズ1のまま変更しない。

## 9. v0.2.0の実装判断（2026-09-12）

- 残り時間は数字＋バー、残り25%以下で警告色。時間の値はStagePlay.limitSecに持つ。
- チャレンジの計測開始は速度0.5マス/s超、または開始位置から0.02マス移動。
  速度判定だけでは微速で時計が始まらないため、実移動でも開始する。練習は従来の速度判定。
- 一時停止・設定・タブ非表示中は時間を除外。復帰後は手動で再開する。
- コンティニューは2回。HPと時間をリセットし、同じシード・難易度・素材配置で再開する。
- 到達面数はクリア済みの面数。UIは「クリア面数」と表示する。
- 合計タイムはクリアした面だけを合算。失敗試行は含めない。
- ノーミス面数を結果に表示。残HPはクリア時にボーナス評価として示すが、面数の加点はしない。
- 最初の失敗時点のノーコン記録を保存し、続行後の成績は使用枠にだけ保存する。
- プレイ中／クリア後にもランを終了して結果を保存できる。
- 練習はランダムシードまたはURLの `?seed=`。床素材・ラン履歴選択は対象外。
- 既存の検証済み素材配置を維持。ゴムは定義・描画にはあるが現在は出現しない。

## 10. v0.2.1 序盤の時間とHPの緩和（T-209）

実機試遊で「最初のレベルから難易度が高い」、原因は「時間が足りない」「HPがすぐ減る」の両方と報告された。
v0.2.0の1面目は400シードで7.15〜23.65秒、中央値13.75秒。初見で道を探しながら操作する余裕が少なかった。
また、初期HPに比例する35%の単発上限では、HP予算だけ増やしても全力衝突3回で失敗する。

そこで基準カーブを維持し、1〜9面目だけ時間・ダメージに緩和を掛ける。

```text
序盤補正 q = max(0, (10 − 面数) / 9)
制限時間 = 経路長 × 基準秒数(面数) × (1 + 1.5q)
ダメージ倍率 = 基準倍率(面数) × (1 − 0.5q)
単発上限 = 初期HP × (0.35 − 0.15q)
```

| 面 | 時間の倍率（従来比） | 通常ダメージ（従来比） | 単発上限 |
|---|---:|---:|---:|
| 1 | 2.5倍 | 50% | 20% |
| 4 | 2倍 | 約67% | 25% |
| 7 | 1.5倍 | 約83% | 30% |
| 10以降 | 1倍 | 100% | 35% |

1面目は17.875〜59.125秒、中央値34.375秒になる。HP100の場合、通常衝突（2.5マス/s）は16.9→8.45、
全力衝突（5.38マス/s）は35→20ダメージ。最初の4回の全力衝突を耐えられる。
閾値1.2マス/s・無敵時間0.25秒・単発上限の仕組みは維持する。

物理・迷路・素材配置・HP初期値・プラクティスは変更しない。10面目以降も従来と同じ。
設定は `gameConfig.DIFFICULTY.intro*` に集約し、`progression` → `createHp` に渡す。
検証用の自動操縦も同じ難易度を渡し、単発上限が本番と食い違わないようにする。

検証: `node --test` 76件成功。100ラン×3条件の中央値12/14/15面、HP0率0/9/45%で従来と一致。
後半の圧力を維持した結果であり、最短経路を知る自動操縦が序盤の人間の難しさを判定するものではない。
実機での再試遊は引き続き必要。既存の保存記録は保持する。
