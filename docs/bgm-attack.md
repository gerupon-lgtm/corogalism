# T-295 / v0.8.1：BGM冒頭の立ち上げ

2026-10-24。ユーザーから、iOSでステージ開始時にBGMがフェードインして聞こえるとの報告。Androidは未確認。追加回答では「最初の一音ぐらい」。過去の類似症状と同じ原因だったかは確認できていない。

## 確認できたこと

v0.8.0では、BGM開始と停止に共通の時間を60msから140msへ延長していた。開始は0から目標音量へ近づく処理のため、短い打音がある曲の出だしを抑える。これはiOSだけの分岐ではなく全端末共通のコード。

実際のSoundManagerをChromeのOfflineAudioContext（機器のスピーカーを通さず音声を計算する機能）で動かし、一定振幅の音を入力して開始の影響を測った。親の音量が落ち着いた後に曲を開始、毎秒60回の状態更新も実行。140ms版では開始20ms付近の10ms平均振幅が定常時の33.6%、100ms付近で88.0%。以前の60ms版は同じ条件で61.2%、99.3%。修正前の実処理で「20ms付近で98%以上」の検証が失敗した。

この結果はアプリ自身の長い立ち上げを再現する。iOSのスピーカー出力やOS側の音声復帰を測った結果ではない。実機で聞かれた症状のすべてを説明したとは断定しない。

## 修正

開始と停止を分離。開始は5msの直線的な音量変化だけにして、冒頭の打音を長く抑えない。全曲の波形冒頭が0とは限らないため、瞬間的なノイズを防ぐ短い処理は残す。停止時は140msを維持。開始音0.8秒＋間0.2秒、毎回先頭からの再生、曲の割当・音源・設定音量・ゲームと記録は維持する。

同じ測定で、10ms付近は99.1%、20ms以降は100%となり検証が成功。関連5ファイル16テストも成功。表示・資材URLは0.8.1、キャッシュ100152b71a2d6cc4・129資材。

## 確認状況

ローカルChromeで1〜17面の5曲の実音声出力、停止・再開、音OFF/ONが成功。曲の先頭開始とループも維持。到達には検証用の位置変更を使い、人の17面完走ではない。ページ・console・通信のエラーなし。公開前。

再測定はtools/probe-bgm-attack.mjs。記録はverification/bgm-attack/before.json、after.json。v0.8.0の前後比較は一定振幅の音で行い、曲ごとの音量・端末の音質の評価とは区別する。iOS／Android実機での再確認は未実施。
