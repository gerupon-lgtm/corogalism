# T-299 / v0.8.5：ヘッダー境界の訂正

2026-10-24 JST。ユーザーの注釈画像で、トップと本編の位置をそろえる境界が明確になったため、v0.8.3の解釈を訂正する。**ローカル確認済み・公開前**。

## 前提と訂正点

固定ヘッダーは、OSバーの下に示された白線から、時間・げんきメーターの上端に示された下の白線まで。ロゴ・バージョン・面数行を含む。迷路枠までの領域ではない。

v0.8.3では、メーターと操作列まで透明な予約領域に含め、トップ木枠を迷路枠の上端へ合わせていた。そのため上部の空白が過大になった。実装と検証の基準を、ユーザーが示した**時間・げんきメーターの上端**へ訂正する。

[v0.8.3の資料](header-and-leaf-v0.8.3.md)は誤解釈を含む当時の履歴として残す。ヘッダーの現行指示はこの資料を優先する。葉っぱの取得不可案内など、別の変更内容はこの訂正の対象ではない。

## 今回の位置合わせ

| 対象 | 方針 |
| --- | --- |
| トップ木枠の上端 | 本編の時間・げんきメーター領域（`time-meter-block`）の上端へ合わせる |
| トップの面数行 | 本編の面数行（`stage-line`）と高さを共有する |
| トップのメーター・操作列 | 表示領域から除外し、高さの予約にも使わない |
| 本編のロゴ・メーター・操作列・迷路 | v0.8.4から実寸と位置を変えない |

面名の折り返しを見積もるための迷路の下見（`renderHomeHeader`）は削除する。トップで共有するのは面数行までなので、操作列の高さを予測する必要はない。

新たな装飾は追加しない。「No-gap確認案r1」を採用する変更でもない。記録・選曲・物理・ゲームのルールは変更しない。

## 確認結果

- Chrome／PC WebKitの各8条件で、トップ木枠上端と本編メーター上端が一致した。312〜844px幅、短い画面、カメラ・下部の余白を含む。
- Chromeでは公開v0.8.4の同じ8条件を先に記録し、本編のロゴ・メーター・操作列・迷路の実寸と位置がすべて完全一致した。
- 390×844px・カメラ余白なしでは、トップ木枠上端は197.046875pxから86.046875pxへ移動し、本編メーター上端86.046875pxと一致。本編の迷路上端197.046875pxは維持した。
- 回転して戻る操作、自己ベストの展開、紹介からトップへ戻る操作も成功。表示バージョンは0.8.5、キャッシュ7ffb5b7b3140b7c6・130資材。公開確認はこれから行う。

最初のローカル確認では、別プロセスの配信サーバーが終了して接続が切れた。確認用の配信を検証と同じプロセスへ移した後、上記の確認が成功した。`baseline/failure.*`・`local/failure.*`はその環境側の失敗記録で、最終結果と分けて残している。
