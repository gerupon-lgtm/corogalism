## 音の方向性

現在のクリーム色のトイUI・光沢球に合わせ、木琴・トイピアノ・柔らかい打楽器を中心にする案。
テンポは90〜105 BPM、短い旋律の30〜45秒ループ。高音を鋭くしすぎず、考えて操作する時間を邪魔しない。
初期案は共通BGM1曲。後からチャレンジ用の軽いリズム差分を加えられる構成にする。

| 場面 | 効果音案 |
|---|---|
| ボタン選択 | 小さい木製ボタンの「コッ」 |
| 3・2・1 | 短く柔らかい3音、開始だけ明るい高音 |
| 転がり | 動く速さに応じた控えめな「コロコロ」。初期試聴で耳障りなら常時音は省く |
| 標準壁 | 丸いビー玉の「コツ」 |
| 石／棘 | 石は低い「カッ」、棘は短い金属音。傷ついたときだけ少し強調 |
| 苔／ゴム | 苔は柔らかい接触音、ゴムは弾む「ポン」。ゴムの配置は別タスク |
| ゴール／クリア | カップに落ちる「コトン」＋1秒程度の上昇フレーズ |
| 失敗／コンティニュー | 失敗は短い下降音、再挑戦は前向きな2音 |
| ポーズ | 小さなクリックとBGMのフェード停止 |

同じ壁への微小接触で音が連打されないよう、衝突の強さ・最短発音間隔・最大同時発音数を設ける。
HP計算の閾値とは別の音量調整として扱い、ゲーム判定を音に依存させない。

## 操作と再生方針の案

- ヘッダか盤面上の操作列に音ON/OFFを1つ。既存のトイ調・押し込みを流用。
- 初回は音OFF、タップで有効化。設定にBGM／効果音の音量を別々に置き、好みをlocalStorageへ保存。
- ブラウザの自動再生制約に合わせ、音の有効化・再開はクリック内で行う。
  モード選択時のiOS傾き許可と競合させず、許可完了後の非同期処理にユーザー操作を持ち越さない。
- ポーズ・設定・タブ非表示でBGMと転がり音を停止。再開後に滑らかに戻す。
- クリア音の間はBGMを少し下げる。連続クリックでもBGMを二重に始めない。
- 無音・読込失敗・音声API非対応でも、カウントやクリア演出はそのまま使える。

## 実装候補

まず短い試聴サンプルで質感を決め、その後にゲームへ接続する。
効果音はWeb Audioの短い合成音、BGMは自作フレーズを同梱ループ音源にする案。
音源を採用する際は出典・利用条件を記録する。実行時LLM・外部音源API・バックエンドは追加しない。

音声管理は `src/audio/` にまとめ、`src/main.js` の開始・停止・クリア・失敗イベントから通知する。
衝突音は既存の衝突イベントを経由し、物理側へAudioContextやDOMを持ち込まない。
同時再生・タブ復帰・音量保存・無音フォールバックをブラウザで検証し、iPhone / Androidで試聴する。

技術確認: [MDN Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)、
[MDN autoplay guide](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)。
本書の曲調・テンポ・音量・初回OFFは提案段階であり、ユーザーの確定指示ではない。
