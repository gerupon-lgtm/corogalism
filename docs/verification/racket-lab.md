# T-285 ラケットと綿の確認

2026-10-10、v0.6.28。実装・単体・ローカルブラウザ確認済み、公開作業中。公開成功や実機試遊を未実施のまま完了扱いにしない。

## 確認範囲

- 単体確認：本編基準との600フレーム一致、綿の沿う滑り、中心／端・縦／横の返球、水平停止、逆向き設定、高速の球と壁、挟み込み時停止、極端な数値と処理停止。
- 配置確認：静止壁の全セル到達、同じ比較形状、両レールの全範囲で球一個以上の退避幅、中継広場の直線とL字直行遮断。
- ブラウザ確認：実pointer・画面幅・描画復旧、模擬センサー、共有、保存設定の読取と本編記録の保持、完全オフライン。
- 未確認：実端末での感触、センサーや音の自然さ、人間の長時間の楽しさ。ブラウザの自動操縦成功で実機の評価を代用しない。

## 単体確認済み

全38ファイルを最大5ファイルずつ8回に分け、217テストすべて成功・終了コード0。[結果](racket-lab/unit/results.json)。新規16テストと既存201テストを含む。本編基準のラケットなしは600フレームの座標・速度・壁接触・解決値が既存処理と完全一致した。

同じ球位置(2.4,5.5)・速度(2,4)・傾き(0.3,0.5)・1/120秒刻みの一例では、下のラケットを使って0.967秒、綿のみでは1.383秒でゴールした。約30%短い条件が成立することをテストに残した。中心へ無傾きで当てる条件は縦へ返るだけで、自動ゴールにはならない。これは局所的な計算例で、人間の平均タイムや面の楽しさを証明しない。

## ブラウザで見つけた点

ゴール後の設定切替で、ゴール状態を保ったまま案内だけが消え、操作できない問題を修正。完了後の切替は新条件のスタートへ戻る。背景移動などで停止していた時は停止を維持し「再開」を案内する。完了中のポーズは無効。

綿の入力1が静止壁の本編処理で0.7になる条件を確認。入力値を消して丸めるのではなく、ラベルと設定欄に本編の上限0.7と実効値を表示する。共有には実際に入力した値を残す。綿の開始値0はそのまま。

312幅の幅変更後に、2画素・各成分最大1/255の輪郭差を観測した。倍率・盤面寸法・不透明画素は一致。資材の読み込み待ちを入れても再現したため、原因を画像読み込みと断定しない。既存の描画復旧確認と同じ最大32画素・各成分1/255の許容を採用し、寸法・倍率・透明化を厳密に確認する。縮小や球の残像を許容する変更ではない。

## ローカルブラウザ確認済み

Chromeの312×720、412×915（Pixel 6a相当のDPR2.625）、576×1024で、画面を押す操作・水平時のラケット停止・ポーズ・切替・共有・描画復旧・幅の往復・球の残像を確認。縦横それぞれ中心／両端の6返球、返球後の傾きの力、同じ壁への綿／ゴム比較、ゴール後切替と実効綿の追加回帰も成功。[最終結果](racket-lab/local-final/results.json)、[厳密画像比較で観測した小差](racket-lab/local-final/strict-resize-failure.json)。

センサー許可・拒否・無応答・非対応の模擬4条件、再基準合わせの無応答、許可を全画面より先に求める順序、本編の31度／消音設定の読取と上書きなし、旧描画資材の更新案内を確認。既存ボールページで114資材を保存し、未訪問の設定付き新ページを完全オフラインで開いて、球と縦横ラケットを実際の画面操作で動かせた。

開始位置から同じ6経由点を目指す自動画面操作（位置移動・debug.advanceなし）で、基準7.408秒・綿7.408秒・ラケット＋綿9.936秒（返球3回）でゴール。通路をたどるだけの制御ではラケット側が遅くなった。到達確認として結果を残し、ラケットを狙って使う人間の速さや楽しさの証拠にはしない。ラケットで方向転換を省く操作の恩恵は、前の局所例と区別して実機で評価する。
