# T-286 ラケット広場の下辺の近道（2026-10-10・v0.6.29）

配置の修正・単体確認・ローカルブラウザ確認済み。公開の最終結果は配信後に追記する。

## 原因と変更

以前は右下の角がゴールだったため、最初の仕切りを越えれば最後は下辺を横へ滑るだけで着いた。T-285の開始からの直線／L字確認は、最後の横移動を対象にしていなかった。開始からの到達確認と、面が反発を使いたくなる設計であることは別の評価であり、前回は後者が不足した。

中継広場だけカップ中心を(6.5,6.5)から(5.5,4.5)へ移し、上と左右に壁を付けて下から入る受け口にした。入口は2マス幅（壁の内側1.76、球の直径0.55）を保つ。上仕切りは同じ、下仕切りは受け口の入口の2区間を開ける。外周をたどるだけでは入れず、下から上への折り返しを要する。

横ラケットは高さ6を保ち、初期xを3.2、右端を4.85へ変更。縦ラケットの最大yは2.0とし、受け口上の壁と球一個以上の隙間を保つ。これは面の壁配置による移動範囲で、反発・傾き・最高速などの新しい上限ではない。打ち分け用の開放広場は従来のまま残す。基準／綿／ラケットの3状態は同じ静止壁で比較できる。

## 確認済み

最大5ファイルの単体確認46件が成功。[結果](racket-goal/unit.json)。下辺の試行開始点に横ラケットとの0.015の重なりを見つけたため、試行点だけy6.58へ変更し、配置8件を再確認した。[最終試行点と確認](racket-goal/probe-check.json)。実際の球や物理を修正したという意味ではない。

全49セルがつながり、3比較で静止壁が同じ。入口の球の余地、上と左右からの直行遮断、下辺だけの移動と旧最後の横移動でゴールしないこと、全可動範囲で球一個以上の退避幅を確認した。本編の氷・ゴム・ビー玉との600フレーム一致、可動壁のすり抜け・挟み込み・有限値保護も再成功。

同じ下段入射(4.375,5.38)、速度(0,4)、傾き(0.3,0)、1/120秒刻みでは、綿だけ0.992秒・横ラケットの端を使うと0.417秒で新カップに入った。中心への入射では2秒以内に入らない例も確認。これは返球を使う局所例であり、プレイ全体の平均タイムや人間の楽しさを証明しない。

ローカルChromeは312／412／576幅で操作・中心／端の打ち分け・数値編集・共有revision2・描画復元が成功。412幅の実pointer自動操作で、3状態とも下辺だけではゴールせず、開始から旧最後の横移動まで到達しても未クリア。その続きで下側の入口から上へ折り返すとクリアした。[全体結果](racket-goal/local-final/results.json)。入力の無効・無応答・非対応を含むセンサー4模擬、保存設定、114資材の未訪問URLオフラインも成功。実端末の傾き確認という意味ではない。

新コースの自動操作は基準8.800秒・綿8.816秒・ラケット9.040秒（返球1回）。局所の同じ入射・同じ画面操作では綿1.008秒・ラケット0.432秒。通路をたどる全体操作では今回もラケットが遅くなった結果を残す。局所返球の速さを、面全体の楽しさ・恩恵へ一般化しない。

## 描画採取の失敗と確認

初回のサイズ往復確認は盤面が全面透明になり失敗した。[失敗結果](racket-goal/local/results.json)。仮想の時計だけを止めた状態でもブラウザの寸法通知は届き、canvasのサイズ変更は絵を消去する。通知後に次の描画を進めると全面不透明へ戻ることを順序記録で確認した。通常の時間で動かす独立したページも透明画素0で復帰した。[順序記録](racket-goal/resize-diagnostic/results.json)。確認側は「寸法通知完了→次の描画→採取」に修正し、透明画素・寸法・倍率の条件は維持。アプリの描画処理は変更していない。

local-finalの旧終点の画面保存にも一枚の空表示があった。同期後には正常な氷の盤面を保存できたが、別のゴール画面で「canvas内は全面不透明、保存PNGは空」という別の失敗を捕捉した。[画面採取の追加記録](racket-goal/local-visual/results.json)。仮想時計下のブラウザの画面合成の採取失敗として残し、アプリの不具合と断定しない。

通常時計の新規412×915／倍率2.625のページで、3状態とも画面を押して400ms動かし、一時停止後のPNGに盤面が写ることを別途確認した。氷の画素率70.1〜73.1%、canvas透明画素0、停止理由・ページ例外なし。[通常時計の結果](racket-goal/real-screen/results.json)、[ラケットの盤面](racket-goal/real-screen/rackets-412.png)。旧終点の正常画像も[別保存](racket-goal/local-visual/old-bottom-finish-412.png)し、旧右下に着いても未ゴールを視認した。失敗した仮想時計のPNGを正常画像へ置き換えない。

## 別案の候補

ユーザー案として、反発を狙う面とは別に「ラケットを順に動かして通路を開ける面」を残す。縦の壁を逃がして球を通し、次に横の壁を動かして次の通路へ進む形。通路の配置で順序が生まれる方法を検討し、操作中に同じ傾きで動く球の待機場所・閉じ込めから戻れる動きが評価点。未実装で、今回の中継広場へ混ぜていない。
