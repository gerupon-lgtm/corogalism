# T-287 動く壁の通路パズル（2026-10-10・v0.6.30）

実装・単体・ローカル／公開ブラウザ操作・通常時計の表示・配信確認を完了。

## 仕組みと変更

同じ傾きで球と壁が動くが、氷の球は速度を残し、壁は入力を切り返すと逆へ移動する。球の慣性と壁の移動の差を使う「順に通路をひらく」「切り返して滑り込む」を専用ページへ追加。旧2広場は残し、本編の生成・物理・入力・描画・音・時間・げんきのソースは変更しない。

順番の面は縦向きの戸を上下、横向きの戸を左右へ動かす。①を下へ開けて右の部屋へ渡り、②を左へ開けて下へ進む。綿の横壁・縦壁に球を待たせ、同じ入力で戸を開ける。操作順は通路の配置から生まれ、ヒット回数や手順番号によるゴール解錠はない。

切り返しの面は横向きの戸が左右へ動き、右入力が下段の入口を閉じる。右へ助走後、左下へ切り返すと、戸が左へ退く間も球は右へ滑る。右側の固定壁のゴム反発を残す。通過後のカップは内側へ置き、下から入り直すので、入口を抜けて横へ送るだけでは終わらない。

通路の戸は球との相対速度から普通に反射する。ラケット用の中心／端の角度操作とは別に扱う。形と移動軸を分離し、従来のラケットの打ち分けは維持。反発・速度・綿の有無などは編集可能で、新しい数値上限は追加しない。全氷と本編の基準球を保つ。

新しい戸は固定壁に重なる収納部分を持つ。閉鎖通路に「全移動範囲で球径以上の隙間」を要求すると戸を閉じられないため、旧2広場の退避幅確認と分ける。静止壁は全49セルの連結をBFS（つながるマスを順に調べる方法）で確認し、動く戸は実際の球の太さと操作順で別に確認する。

統合レビューで途中の設定切替の不具合を確認。球を四角として判定すると、安全な戸位置を誤って除外し、レール両端で重なっても最後の端へ戸を出していた。円と矩形の距離へ修正し、レール全体を球がふさぐ場合は切替を取り消して以前の設定・盤面・球を保持する。理由と移動／スタートへ戻す操作を案内し、素材や面を検証候補から外さない。

## 単体・計算で確認した範囲

最大5ファイルの単体確認54件が成功、終了コード0。[実行記録](racket-puzzles/unit.json)。既存の氷・床・係数解決、600フレームの本編との一致、旧ラケット中心／端、新しい形と移動軸の組み合わせ、普通の反射、挟み込み停止と切り返し脱出、静止壁の連結、新面の動的な到達を確認した。

順番の面は、①閉／②閉、①開／②閉、①閉／②開、両方開の状態で球の太さを含む通過を確認。両方を開けるとゴールへ通じる。綿へ球を預け、開始から位置・速度を置き換えず、1/120秒刻みの自動操作で20.983秒で到達。

切り返しの面は同じ局所入射(4.3,2)、速度(4,1.5)、閉じた戸位置x4から比較。すぐ左下へ入力を変えると0.625秒で球全体が下段へ通過。右下入力を0.2秒残してから切り返すと、最初の1秒では抜けず固定壁で上へ返る。これは用意した初速による局所比較で、開始からのプレイと分ける。

初期位置から右への助走・左下への切り返し・下段の狙い直しを計算し、位置や速度の置換なしで9.083秒で到達。切り返しのxを4.05／4.2／4.3／4.4に変えた4条件でも通過。これらは自動操作の成立確認であり、人間の操作精度・楽しさ・Pixel 6a実機の快適さは未確認。
