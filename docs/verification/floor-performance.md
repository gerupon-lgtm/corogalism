# T-259 処理落ちと迷路重複の修正（v0.6.1 / 2026-10-02）

## 報告と原因

ユーザーがやさしい3面で処理落ちしてプレイ中断。砂が見えており最新の床導入版であることを確認した。砂の摩擦ではなく、v0.6.0の描画実装で静止床と全コルク壁を毎フレーム描き直していた。壁の影・粒模様が重く、物理は長いフレームを50msで切る一方で時計は実時間で進むため、遅い端末では転がりまで遅く見える。

全体ランから面のシードは変えていたが、隣接面の増分40503と、6候補を作る増分40503が同じだった。候補集合が重なり、例えばラン77の2・3・4面がすべて迷路シード102436になる。同じ迷路を意図的に使っていたものではない。

## 修正

- 静止した通常床・氷・砂と壁を、面・サイズ・端末倍率・壁画像の準備状態が変わった時だけ描く。壁を透明な別Canvasへ保存し、動的な力場の上に一括合成する。
- 粒子・力場・球・取得物・ゴール演出は動的描画を維持。タイトル・設定・結果では盤面描画を止める。
- 候補は各面のシード固有の疑似乱数列から作り、隣接面と共有しない。初登場の力場がない場合は最大24候補まで有限回追加する。同じラン・同じ面の再現性とコンティニューは維持。
- 砂の減速・氷の慣性・壁のダメージ・制限時間は変更しない。記録はv0.6.0と同じ床ルール枠を維持。

## 確認

シード重複の回帰テストは修正前に失敗、修正後に成功。報告再現用4ラン＋100ランの1–4面、決定的再現、力場配置各1000シードを確認。145自動テスト成功。[結果](floor-performance/unit-tests.txt)。新候補生成で両難易度30シード×20面の1200操縦ケースも再確認した。

`browser-floor-performance.mjs` はCPU6倍の負荷と端末倍率1／3で、ウォームアップ後40回の描画を測る。修正前の3描画モジュールだけをgit9055804から読み込み、同じ迷路シード・同じ壁数・同じ倍率の修正後と比較する。

既存のchallenge4幅、floor-lab3幅とセンサー／オフライン、tutorial3幅とセンサーの回帰成功。静止キャッシュの更新・動的力場の重なり・非ゲーム画面停止・候補生成の読み取りレビューでCritical/Important指摘なし。
