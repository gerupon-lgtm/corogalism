# 後半の壁素材: 実装と確認（2026-10-25）

この記録は新規 `src/world/progressiveWalls.js` の確認結果。公開や実機の遊び心地を確認した記録ではない。

## 呼び出し契約

- `applyProgressiveWalls(stage, difficulty)` は生成済みの stage を更新し、同じ stage を返す。
- 通常の床・パズルの素材設定が終わってから、一つの stage につき一度だけ呼ぶ。`createStagePlay` の stage 構築直後なら両系統を同じ入口で扱える。
- `difficulty.themed` が真、33面以降、氷・砂・力場がある、またはパズルの面だけが対象。32面以前と対象外は監査情報も追加せず完全に維持する。
- 設定は root 担当が追加した `PROGRESSIVE_WALLS` を参照。以後の面数によって配合確率を増やす処理はない。
- 原配合は既存の素材のまま。もともとのコルク・石・とげを無傷にする意味ではない。

## 配合と保護

- やさしいは原配合50%・混在40%・アクセント10%、通常は45%・40%・15%。種と面番号から独立した乱数列を作る。
- 混在は候補区間ごとに通常20%・石8%、アクセントは通常25%・石12%・とげ3%。それ以外は既存の素材を残す。
- 混在・アクセントなのに変更がゼロだった場合だけ、候補から一つ選び、配合の比率で一素材を抽選する。既存素材と同じになる選択はこの救済抽選から外す。全種類を最低一つずつ強制しない。
- 外周・綿・石・とげ・こけ・ラケット・独自の物理設定を持つ壁は再置換しない。開始・ゴールから1マス以内、戸口の両端と待機点から1マス以内の区間を保護する。
- 長い壁は1セル＋既存の壁厚を目安に区切り、変更する区間がある壁だけ表示用の `stage.walls` へ分割を実体化する。既存の一マス以下の壁を分割しない。
- 長壁を一つでも分割した面だけ `stage.collisionWalls` を追加する。衝突用は元の壁の順序・個数・矩形を保ち、変更した長壁の要素は元の `materialId` と、未変更片を含む全表示区間の `materialRegions: [{x,y,w,h,materialId}]` を持つ。非長壁の素材変更は衝突用にも反映する。原配合・分割なしの面へ新しい衝突配列を足さない。
- 候補がなければ配合名が混在・アクセントでも壁は変更しない。素材の欠けは監査情報の `shortfall`（新規変更がなかった素材IDの配列）に残す。

## 監査情報

`stage.wallVariety` に `profile`、種・面数・難易度、`eligibleSegments`、`protectedSegments`、`changedSegments`、`changedCounts`、`minimumChanged`、`splitWalls`、入力・出力区間数、期待区間数、`shortfall`、`countsBefore`・`countsAfter` を保存する。分割前後の区間数は壁の長さや衝突確率と同じではない。

## 確認結果

- 対象 `test/progressive-walls.test.js` の7テスト成功（衝突用配列の追加後、約0.97秒）。32面以前と対象外の完全不変、種の再現、全配合と全追加素材、少候補の最低変更数、保護対象、表示矩形の合併を確認。
- 衝突用の個数・順序・矩形が元の配列と厳密一致し、素材区間が未変更片を含めた表示用の全区間と対応することを確認。短壁の素材反映、分割なしで新しい配列を追加しないこと、循環参照・関数を含まずJSONへ直列化できることも確認。
- 7/13マス×3種×通常面と全6パズル（計42生成）で、迷路・床・可動壁・時間負担の入力、BFS到達性、戸口と待機場所の球径検証を維持。
- 33/100/1000面・両難易度・各256種の有限標本で、原配合が残り、各配合が消えず後半に一律化しないことを確認。
- 変更後の実生成は `progressive-distribution.json` と `progressive-summary.md`。32種類のラン×100面×両難易度の6,400面を生成し、履歴を維持した。
- 変更候補のないパズルがやさしい13面／通常12面あった。原配合以外を引いたのはそれぞれ3面／4面で、保護を優先して変更せず記録している。

## 衝突契約の訂正

当初は、分割片の合併が元の矩形と一致すれば形状を維持できるとした。しかし別担当の限定再現で、同じ素材でも継ぎ目が角として扱われ、12条件中5条件で接線方向の速度とダメージが変わったとの報告があった。表示矩形の合併確認だけでは物理の維持を確認できない、という前提へ訂正した。

このため上記の衝突用配列を追加する契約へ変更した。別担当が当たり判定の参照先を `stage.collisionWalls ?? stage.walls` とし、接触点の素材を `materialRegions` から選ぶ処理を担当する。今回の担当範囲では、その物理処理との統合・再現条件の解消は未確認。6,400面の表は表示素材の配分の記録であり、実際の衝突やダメージの証拠ではない。

未確認: 物理担当の修正との統合後の衝突・ダメージ・可動壁の動的操作、端末での傾き、長時間の遊び心地。
