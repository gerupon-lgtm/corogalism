## 表現の確認

- 既存の緑の床、橙の球、紫の動く壁、実際の素材・取得物描画を共有している。
- ゴムは大きく返り、石・こけは小さく返る。コルクと標準の反発は同じ。綿は壁へ向かう動きを止めて壁沿いに進む。これは動きの説明図で、被害量や反発距離の計測値ではない。
- 氷は進み続け、砂は早く減速する。重力は中心へ曲がり、反重力は外へ曲がる。休憩では停止して回復表示、とりもちでは2回のタップ表示後に縮小する。
- ラケットは前半に中心で真横へ返球、後半に壁をずらして端から斜めへ返球する。6000msの終端では球が左上へ戻っており、衝突前で停止していない。
- 戸を右へ開いた後、球が通路を上へ通る。矢印・軌跡が残り、動きを減らす設定でも元の位置と移動方向が読める。
- キャンディ・休憩の回復バーは40%から60%へ増える。バー中央の塗りをピクセルで読み、両方とも36px幅中14→21pxと確認した。表示の20%回復は既存のRECOVERY/REST設定を参照する。
- 戸の見本は0〜1800ms右へ開く→1800〜2500ms左へ戻す→2500〜3800ms上へ通る→水平。左戻しでは戸もx96から90へ戻り、球が通れる隙間を残す。ラケットは3000〜3500msの壁移動だけ下へ傾け、返球後は水平にする。
- 戸の1000/2100/3100/4000ms、ラケットの3200/6000msのスマホ図を、右/左/上/水平/下/水平の基準図とそれぞれピクセル比較し一致した。他の比較画像のスマホ方向は右。APIの方向は右が+x、下が+yで、茶色の矢印が方向を示す。実プレイの次の操作は別の案内表示であり、ここでは見本の操作と区別している。

## 初回の失敗と修正

初回は19種類すべてで、細かく再生した球の模様と終端だけを描いた球の模様が異なった。共用球が過去の移動から回転を積算していたため。`tutorialDemo.js` 内だけで各位置から球の向きを再現する処理へ修正し、再確認で解消した。`results-initial.json` と `*-initial.png` は修正前の証跡。

独立レビューで回復バーが40→100%となっていたこと、戸とラケットの操作図が見本の動きと同期していなかったことを指摘された。回復量を実ルールの20%へ合わせ、操作図を見本の各段階へ同期し、上記8項目を追加して再確認した。

初回のfavicon取得には404があったため、検証用ページではfaviconだけ204を返して無関係のエラーを避けた。修正後最初の再実行では一時的にモジュール取得が失敗した。同じURLを個別取得するとHTTP200・text/javascriptで、限定再試行と最終実行は成功した。取得失敗の原因は未確定であり、成功結果で置き換えて原因が解消したとは扱わない。
