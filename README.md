# コロガリズム / Corogalism — フェーズ0（操作感の検証）

傾き操作の迷路ゲーム「コロガリズム」の、**判断のための最小プロトタイプ**。
7×7の迷路を1画面に収め、傾き操作と擬似傾き操作で転がして、パラメータの当たりを取る。

- ビルド不要。`index.html` 1枚だけ。
- 生成AI（LLM）は不使用。迷路はDFSバックトラッカーでブラウザ内生成。
- 迷路生成・自動生成の本実装はフェーズ1。ここでは操作感だけを見る。

## 置き方

リポジトリ: <https://github.com/gerupon-lgtm/corogalism>
公開URL: <https://gerupon-lgtm.github.io/corogalism/>

`index.html` をリポジトリ直下に置き、Settings → Pages で `main` ブランチのルートを公開に設定する。

**傾きセンサーはHTTPSでしか動かない。** 開発機のLAN IP（`http://192.168.x.x`）にスマホから
繋いでもセンサーは反応しない（`localhost` は例外だが、スマホからは開けない）。
PC側では `localhost` で擬似傾きモードを使って調整し、**傾きモードの確認だけデプロイして実機で行う**。

`noindex` を入れてあるので、検索から人が来ることはない。ポートフォリオからのリンクはフェーズ3まで行わない。

## 使い方

1. スマホで開き、**楽に持てる角度で構えてから**「この向きを基準にして始める」を押す
   （iOSはここで一度だけ許可を聞かれる。許可しない場合は自動で擬似傾きモードになる）
2. 転がしてゴール（右下の輪）を目指す
3. 「操作パラメータ」で感度・摩擦・最大傾き角・反発を調整する
4. 「合格ラインの判定」で a・b を10回ずつ記録し、c のドリフトを計測する
5. 合格したら「調整した値の書き出し」のJSONを控える（フェーズ1の `gameConfig` 初期値になる）

## 合格ライン（すべて満たせばフェーズ1へ）

| # | 基準 | 判定 |
|---|------|------|
| a | 幅1マスの通路を壁に当たらず端から端まで通せる | 10回中8回以上 |
| b | **狙った1マスの隙間に入って止められる** | 10回中7回以上 |
| c | 静止5秒でボールが1マス分以上流れない | ドリフト計測 |
| d | Pixel 6a と iPhone XR の両方で a〜c が成立する | 両機で実施 |
| e | 30秒続けて腕が辛くない傾き角で a が成立する | 実感で判定 |

**b が最重要。**「動かせる」と「止められる」は別の話で、迷路ゲームの成否は後者で決まる。
a だけ通って b が通らないときは、摩擦を上げるか感度を下げる。速すぎて弾かれるなら反発を下げる。

d が片方だけ通った場合は、センサーの値域・座標系を吸収する実装を足してから再判定する。
調整しても a・b が通らない場合は、企画そのものを見直す（フェーズ0を判断ポイントとして機能させる）。

## 既知の制限（フェーズ0の割り切り）

- 縦持ち前提。横向きにすると傾きの軸がずれる（警告だけ出す）
- 迷路は7×7固定。難易度・ギミック・スコアはフェーズ1以降
- 記録の永続化は操作パラメータのみ（localStorage）。判定記録はリロードで消える
